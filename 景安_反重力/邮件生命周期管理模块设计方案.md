# ES Mail 本地邮件归档 - 邮件生命周期管理功能设计方案 (PRD)

---

## 一、需求背景与目标

### 1.1 业务背景
在企业邮件合规归档场景中，随着存储时间的推移，归档数据量成倍增长。为了满足企业数据合规审计标准（如保密期限、GDPR、网络安全法要求）并优化本地硬件存储与 Elasticsearch（以下简称 ES）索引开销，系统需要一套完善的**邮件生命周期自动清理机制**。

### 1.2 核心目标
1. **菜单归属**：在系统的【辅助工具】栏目下增加【邮件生命周期策略】管理模块，以及在日志栏目下增加【生命周期日志】。
2. **策略制定**：支持管理员灵活按**年、月、日**指定邮件最长保存期限（支持针对全员、指定部门、指定账户或域名生效）。
3. **自动化双向销毁**：系统后台调度自动彻底清理超期的**邮件本体文件（.eml/.msg 及附件）**和 **ES 数据库中的元数据/全文索引**。
4. **多方命中判定逻辑（核心防误删保护机制）**：
   - 当一封邮件同时命中多个删除策略（例如发件人、收件人、抄送人、密送人所属的生命周期策略各不相同）时，采用**最长保留原则（所有关联方均满足删除条件时才执行物理销毁）**，并在界面关键位置提供**高亮引导图标与鼠标悬浮解释弹层（Popover）**。
5. **审计闭环追踪**：自动记录生命周期删除操作的审计日志，支持查看执行批次、清除邮件数、清空ES索引条数、释放磁盘空间及抽样明细清单。

## 三、核心功能与交互说明

### 3.1 导航栏目层级与位置规划（精准对齐系统架构）
- **【企业配置】（一级栏目）**：
  - 展开子栏目中，在【归档配置】的正下方增加 **`生命周期`**（与归档配置同级并命名为“生命周期”，带高亮 NEW 徽章，点击在右侧打开标签页）。
- **【辅助工具】（一级栏目）**：
  - 保持原功能完整：归档备份、标签管理。
- **【日志管理】（一级栏目）**：
  - 作为独立的一级栏目展开，在其原有的 9 项日志（搜索日志、备份日志、登录日志、告警日志、归档日志、审计任务日志、审计邮件日志、同步日志、第三方邮箱日志）之下，新增 **`生命周期日志`**，用于审计追踪所有自动与手动的邮件清理记录。

### 3.2 邮件生命周期策略配置（弹窗表单 Modal）

#### 表单字段规范：
| 字段名称 | 控件类型 | 必填 | 默认值 / 选项 | 交互说明与约束 |
| :--- | :--- | :---: | :--- | :--- |
| **策略名称** | 单行文本框 | 是 | 空 | 限制50字以内，如：*“常规员工邮件保存3年策略”* |
| **适用范围** | 下拉选择框 + 输入框 | 是 | 全部邮件 | 选项：`全部邮件`、`指定组织架构/部门`、`指定邮箱账户`、`指定企业域名`。非全部时展开输入框支持逗号隔开 |
| **邮件保存时间** | **年/月/日 组合输入** | 是 | `3` 年 `0` 月 `0` 日 | 3个数字微调输入框联动，不可全为0。**右侧附带引导问号图标** |
| **多方判定规则** | 警告提示卡片（Callout） | - | 常驻提示 | 提示：“发件人、收件人、抄送人分别命中了删除策略，则均满足删除时才会删除此邮件” |
| **执行清理对象** | 复选框（联动选中） | 是 | `[✔] 删除邮件本体` <br> `[✔] 清除ES数据库相关信息` | 默认且强制双选，保证本地存储文件与 ES 检索元数据彻底同步销毁 |
| **执行规则** | 单选按钮组 + 时间选择器 | 是 | 定时自动清理（每日 02:00） | 可选：`定时自动清理` 或 `仅手动执行`。定时模式可配置每日闲时调度时间点 |
| **策略状态** | 开关 Switch | 是 | 开启 (true) | 开启后纳入系统每日自动巡检删除任务队列 |

### 3.3 悬浮引导图标与删除策略判定弹层（Popover）

#### 呈现位置：
1. **策略列表主页面**：页面标题右侧的常驻标签 `[? 删除判定规则说明]`。
2. **策略配置弹窗**：【邮件保存时间】字段右侧的 `(?)` 帮助图标。

#### 悬浮内容说明文案：
> 💡 **邮件生命周期多方判定规则说明（最长保留原则）**：
>
> 1. **交集保全机制**：一封邮件通常关联多个主体（**发件人、收件人、抄送人、密送人**）。若不同主体命中不同的生命周期策略（例如：发件人策略为保存 1 年，收件人策略为保存 3 年）：
>    - **判定结果**：系统在第 1 年不会执行物理删除；只有当该邮件关联的**所有人员策略均满足删除条件（即达到最长保存期限 3 年）时，系统才会真正从磁盘和 ES 数据库中清除此邮件**。
> 2. **数据一致性与合规性**：
>    - 避免因为发件人账号过期清理，导致收件人（如财务合规方）无法查阅该邮件原本合规留存的数据。
> 3. **销毁完整性**：
>    - 满足删除条件后，系统将同时物理粉碎本地邮件存储本体（.eml/.msg 文件及附件），并批量提交 ES Delete 请求销毁索引文档。

### 3.4 生命周期清理日志（审计追踪与合规保证）

#### 策略变更/删除后的日志筛选机制（核心合规设计）：
在企业邮件合规归档场景中，**审计日志具备最高法定效力，必须保证历史真实性与不可篡改性**。为此，系统采用“**双轨绑定机制（唯一不可变 Policy ID + 历史名称快照）**”：
1. **策略改名场景**：
   - 当管理员修改了策略名称后，历史日志既保留触发时的**快照原名**，又通过 `Policy ID` 动态关联至**最新名称**；
   - 管理员在日志搜索框输入【最新策略名称】、【改名前原名】或【策略ID】均可查到该策略全生命周期的执行历史。
2. **策略删除场景**：
   - 策略在配置列表中被删除后，**底层审计日志永久保留，严禁物理级联删除**；
   - 对应历史日志自动标注 `[已删除策略]` 标签；
   - 管理员在日志检索栏输入原策略名或策略ID，依然可以完整检索并审计该策略在存续期间的所有清理记录与抽样凭据。

#### 列表字段：
- **执行批次ID**：如 `TASK-20260929-0200`
- **命中策略名称**：点击可直接跳转/筛选该策略
- **执行开始/结束时间**：精确到秒
- **扫描到期邮件数**：系统预检命中的邮件量
- **物理本体删除数**：成功销毁的本地邮件本体数量（如 `14,208 封`）
- **ES 索引清理数**：成功从 ES 索引集群抹除的记录条数（如 `14,208 条`）
- **释放存储空间**：清理后系统释放的磁盘容量（如 `24.5 GB`）
- **执行状态**：`成功`（绿色）、`部分异常`（橙色）、`执行中`（蓝色）
- **操作**：
  - **【查看明细】**：弹出 Modal 展示抽样清理邮件的主题、收发件人、发送时间、原存储路径与 ES Doc ID。
  - **【导出日志】**：导出审计格式的 CSV/Excel 清理报告。
