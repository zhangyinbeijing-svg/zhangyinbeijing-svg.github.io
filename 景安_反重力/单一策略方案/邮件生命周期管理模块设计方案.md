# ES Mail 本地邮件归档 - 邮件生命周期管理功能设计方案 (单一策略方案 PRD)

---

## 一、方案设计背景与定位

### 1.1 业务背景与演进
在原多策略方案中，系统支持管理员创建多条生命周期策略并按部门、用户、域名划分适用范围，由于发件人、收件人、抄送人可能命中不同的保存期限，因此需要引入相对复杂的多方冲突判定机制（如交集最长保留原则）。

而在许多中大型企事业单位、集团合规审计及本地化归档场景中，企业管理层通常采用**统一的数据留存与合规销毁规范**（例如：全企业所有邮件统一保留 3 年或 5 年，到期后统一无差别物理销毁与索引清除）。

针对该场景，推出了**【单一策略方案】**：
- **全系统仅维护一个全局唯一的系统生命周期策略**；
- **无需配置策略名称**（系统内唯一，无需区分标识）；
- **无需配置适用范围**（针对全系统所有归档邮件统一生效）；
- **无需多方判定规则**（所有关联方遵循完全相同的时间时效，无冲突可能）；
- **策略列表页升级为清理日志直呈**：生命周期主页面上方直接呈现系统策略配置看板，下方直接呈现执行清理的审计日志列表，操作层级极致精简，一目了然。

## 三、核心功能与字段规范

### 3.1 导航归属
- **【企业配置】->【生命周期】**：主入口。页面直观展现当前全局策略状态，并直接呈现实时清理日志。
- **【日志管理】->【生命周期日志】**：快捷审计入口，点击无缝切换至生命周期清理审计列表。

### 3.2 系统单一策略配置卡片（页面顶部常驻）
系统顶部以精致的卡片（Banner）形式常驻展示：
1. **策略名称**：固定为“全系统邮件统一生命周期管理策略”；
2. **运行状态**：运行中（绿色状态灯）/ 已停用（灰色）；
3. **核心保存期限**：以大字号醒目呈现当前设置的 `X 年 Y 月 Z 日`；
4. **调度规则**：显示如“每日 02:00 定时执行”或“仅手动触发执行”；
5. **清理覆盖对象**：邮件文件本体（.eml/.msg）+ ElasticSearch 数据库元数据与索引；
6. **上次执行结果**：上次成功执行时间点及清理释放空间；
7. **快捷操作**：
   - **【配置策略】**：弹出精简设置弹窗；
   - **【立即执行清理】**：管理员临时手动触发一次生命周期扫描与物理销毁任务。

### 3.3 系统策略设置弹窗（Modal）字段定义
相比原多策略方案，彻底精简了复杂表单项：

| 字段名称 | 控件类型 | 必填 | 默认值 | 变更说明与规范 |
| :--- | :--- | :---: | :--- | :--- |
| **策略名称** | - | - | - | **【移除】** 系统全局唯一策略，无需设定名称 |
| **适用范围** | - | - | - | **【移除】** 统一针对全系统所有邮件生效 |
| **多方判定规则** | - | - | - | **【移除】** 全员邮件按统一定时超期清理，不存在冲突 |
| **邮件保存时间** | **年/月/日 组合数字框** | 是 | `3` 年 `0` 月 `0` 日 | 超过此保存期限的邮件，将由系统自动触发销毁 |
| **执行清理对象** | 复选框（锁定双选） | 是 | `[✔] 删除邮件本地存储` <br> `[✔] 清除ES元数据索引` | 保证数据彻底销毁与检索一致性，两项联动强制执行 |
| **执行规则** | 单选按钮组 + 时间选择器 | 是 | 定时自动清理（每日 02:00） | 支持定时自动调度（避开业务高峰）或仅手动执行 |
| **策略状态** | 开关 Switch | 是 | 开启 (true) | 开启后每日按时自动执行清理 |

### 3.4 清理日志列表直呈（核心交互）
- 原方案需要进入子页面或切换标签才能查看日志，在单一策略方案中，**策略列表页直接替代为清理日志列表**；
- 支持字段：
  - **执行批次ID**：唯一任务批次编号（如 `TASK-20260929-0200`）；
  - **执行开始/结束时间**；
  - **扫描到期邮件数**；
  - **物理本体删除数**（.eml/.msg 文件及附件）；
  - **ES索引数据清理条数**；
  - **释放存储空间**（如 24.5 GB）；
  - **执行状态**（执行成功 / 正在执行 / 部分完成）；
  - **操作**：【抽样明细】（查看抽样20封销毁邮件的主题、发件人、收件人、存储路径、ES doc ID等）。
- 配备完整的关键词搜索、起止日期筛选、执行状态过滤、一键重置及 CSV 导出功能。

## 四、方案核心优势对比

| 对比维度 | 原多策略方案 | 单一策略方案 (当前方案) |
| :--- | :--- | :--- |
| **策略数量** | 允许多个（不同部门/人员/域名分别配置） | 全系统仅允许设定 **1 个统一策略** |
| **策略命名** | 需管理员逐个命名 | **无需命名**（统一为系统生命周期策略） |
| **适用范围** | 需指定部门、邮箱账户或域名匹配 | **全系统邮件统一生效**，无需选择 |
| **多方冲突处理** | 需最长保留交集规则、悬浮解释 Popover | **无需多方判定**，逻辑简单清晰 |
| **页面操作流** | 策略列表 + 切换/打开日志标签页 | **顶部系统策略看板 + 下方清理日志直呈**，合二为一 |
| **适用企业类型** | 跨部门合规要求差异大的复杂企业 | 绝大多数对数据有统一归档时效要求的企事业单位 |
