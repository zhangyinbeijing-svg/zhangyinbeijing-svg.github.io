# 景安 ES Mail 本地邮件归档 - 搜索员/审计员管理域名与限制功能设计方案 (PRD)

---

## 一、需求背景与业务目标

### 1.1 业务背景
在集团型企业、多分支机构、大型政企或托管式邮件归档服务场景中，**景安 ES Mail 本地邮件归档系统**通常统一对接并归档多个不同域名的企业邮箱系统（例如集团总部 `headquarters.com`、子公司 A `corp-a.com`、海外分部 `dev.cn`、子公司 B `subsidiary-b.com` 等）。

为实现分权管理，系统支持为每个独立域名或子公司分配专属的**邮件搜索员**或**邮件审计员**账户。
- **搜索员**：负责对归档邮件进行日常合规搜索、调阅。
- **审计员**：通过特定条件提取相对应邮件进行专项审计监管，同样属于邮件管理范畴。

### 1.2 现有功能的痛点与业务挑战
1. **现有功能现状**（见参考原图）：
   - 搜索限制：可设置“禁搜关键词”（支持多个），可设置“收件人限制条件”（设置禁搜名单 或 设置可搜索名单）。
   - 审计限制：机制相同，支持设置禁搜关键词和收件人黑白名单。
2. **存在的两大缺陷**：
   - **单向收件人限制无法覆盖外发邮件**：现有的“收件人白名单”仅对收件人地址进行校验。当本域员工（如 `zhang@east.net`）向外部客户发信时，外发邮件的收件人是外部地址，搜索员将无法搜索到本域员工发送的外发邮件，造成严重的监管漏洞。
   - **缺乏多域数据隔离边界（存在跨域越权风险）**：如果没有域名层级的顶层数据范围约束，子公司搜索员不仅能搜自己域，还能搜索其他子公司乃至总部的敏感高管往来邮件，引发企业内部严重的数据合规漏洞（IDOR / 水平越权）。

### 1.3 核心设计目标与调整原则
1. **列表页维持原有页面**：账户管理列表页维持原参考图页面结构（包含标准 9 列与状态值 `• 开启` / `• 停用`），保持原有视觉简洁与操作习惯。
2. **管理域名提升为独立同级模块（先定域，再定限制）**：
   - 在【修改账户】/【添加账户】弹窗中，将**【管理域名】提升至与【搜索限制】、【审计限制】完全同级的一级模块**，排在基础信息之后、搜索和审计限制之前。
   - **配置时序更科学**：先设定该账户管辖哪个域（或哪几个域），该域名发出和收到的所有邮件均纳入该账户的管辖范围；
   - 随后设置的【搜索限制】与【审计限制】均在该管理域名的数据池基础上叠加生效。
3. **双向发收贯通判定（核心规则）**：
   - 管理的范围必须是**“此域发出和收到的所有邮件”**。
   - 即：只要一封邮件的**发件人（From）**属于该域，**或者**其**收件人/抄送人/密送人（To/Cc/Bcc）**任一主体属于该域，均判定为命中该域，允许该搜索员检索与查看。
4. **状态值完整对齐与闭环**：在账户基础信息中补充“状态”配置（开启/停用 Switch），并与列表页中的状态列保持一致。

## 二、核心业务逻辑与判定模型

### 2.1 邮件归属域判定算法（双向覆盖）

设为该账户配置的管理域名集合为：
$$D = \{ domain_1, domain_2, \dots, domain_n \}$$

对于系统归档的任意一封邮件 $M$，其关联的域名集合包含：
- 发件人地址域名：$FromDomain(M)$
- 收件人/抄送人/密送人地址域名集合：$RecipientDomains(M)$

定义该邮件关联的全部域名集合：
$$AllDomains(M) = \{ FromDomain(M) \} \cup RecipientDomains(M)$$

#### 判定规则：
$$\text{IsVisible}(M, D) = 
\begin{cases} 
\text{True}, & \text{若 } D = \text{“全部域名 (不限)”} \\
\text{True}, & \text{若 } AllDomains(M) \cap D \neq \emptyset \\
\text{False}, & \text{若 } AllDomains(M) \cap D = \emptyset 
\end{cases}$$

#### 典型业务场景校验矩阵：

| 序号 | 邮件发件人 (From) | 邮件收件人/抄送 (To/Cc) | 设定管理域: `east.net` | 判定结果 | 业务场景说明 |
| :---: | :--- | :--- | :---: | :---: | :--- |
| **1** | `alice@east.net` | `bob@east.net` | 命中 (发+收) | ✅ **允许管理** | 域内内部互发邮件 |
| **2** | `alice@east.net` | `client@external.com` | 命中 (发) | ✅ **允许管理** | **本域员工外发业务邮件（核心诉求）** |
| **3** | `supplier@partner.cn` | `alice@east.net` | 命中 (收) | ✅ **允许管理** | **外部往来收信进入本域** |
| **4** | `ceo@headquarters.com` | `cfo@headquarters.com` | 未命中 (无关域) | ❌ **物理隔离** | 总部敏感邮件，搜索员无权查看 |
| **5** | `user@corp-a.com` | `client@external.com` | 未命中 (无关域) | ❌ **物理隔离** | 兄弟子公司邮件，彼此完全数据隔离 |

### 2.2 递进过滤漏斗模型 (Filter Funnel)

在实际执行搜索或审计提取时，邮件依次穿过三道防线：

```
                    ES Mail 底层归档全量邮件池
                                │
                                ▼
  【第一层：管理域名 (Data Boundary)】 ◄── 优先设定的同级基础模块
   判定邮件发件人或收件人是否命中指定的域名（单域或多域）
                                │ 过滤非本域邮件
                                ▼
  【第二层：禁搜关键词 (Keyword Blacklist)】
   检测邮件主题、正文是否命中禁搜词（命中则剔除）
                                │ 剔除敏感词
                                ▼
  【第三层：收件人黑白名单 (Recipient Rules)】
   执行收件人黑名单排除或白名单准入
                                │
                                ▼
                 最终呈现在搜索员/审计员界面的邮件结果
```

### 3.3 交互关键细节说明

1. **同级模块架构与配置时序**：
   - **先定域，再定限制**：将“管理域名”置于第一同级模块，作为该账户的基础管理数据沙箱（Data Boundary）；
   - **双向覆盖生效**：该域发出的邮件和收到的邮件全部受该账户管辖；
   - 后续的【搜索限制】与【审计限制】在该域名过滤后的邮件池上继续叠加关键词和收件人过滤。
2. **角色联动机制**：
   - 当在【角色】多选框中包含【搜索员】或【审计员】时，【管理域名】模块展示；
   - 包含【搜索员】时，展示【搜索限制】；包含【审计员】时，展示【审计限制】；
   - 两项均未包含时，下方三个限制模块自动收起，保持基础账户信息清爽。
3. **域名 Tag 智能录入与快捷工具**：
   - 支持回车、逗号连续录入多个域名；
   - `[＋填入验证邮箱域名]`：一键抓取上方验证邮箱域名后缀（如 `@east.net`）；
   - `[＋从已归档域名选择]`：一键点选系统已接入归档的企业域名。
4. **状态值完整闭环**：
   - 弹窗内补充“状态”（开启/停用 Switch 开关），与列表页状态列实时联动。

## 四、技术实现与 ES (Elasticsearch) 检索改写

### 4.1 数据库持久化字段设计

在系统账户表 `sys_user` 中，增加账户管理域名配置字段：

| 字段名称 | 数据库类型 | 允许NULL | 默认值 | 字段说明 |
| :--- | :--- | :---: | :--- | :--- |
| `domain_mode` | `varchar(16)` | 否 | `'ALL'` | 管理域名模式：`ALL` (全部域名)、`SPECIFIED` (指定域名) |
| `managed_domains` | `text` / `json` | 是 | `NULL` | 指定管理域名列表（JSON 数组，如 `["east.net", "corp-a.com"]`） |
| `status` | `tinyint(1)` | 否 | `1` | 账户状态：`1` 开启，`0` 停用 |

---

### 4.2 Elasticsearch 查询改写 (Query DSL Rewrite)

当具有管理域名限制的搜索员/审计员在后台检索邮件时，后端引擎自动在最外层注入强制性 `filter`：

```json
{
  "query": {
    "bool": {
      "filter": [
        {
          "bool": {
            "should": [
              { "terms": { "sender_domain.keyword": ["east.net"] } },
              { "terms": { "recipient_domains.keyword": ["east.net"] } },
              { "terms": { "cc_domains.keyword": ["east.net"] } },
              { "terms": { "bcc_domains.keyword": ["east.net"] } }
            ],
            "minimum_should_match": 1
          }
        }
      ],
      "must": [
        /* 用户前台输入的搜索条件 */
      ],
      "must_not": [
        /* 命中的禁搜词及收件人黑名单 */
      ]
    }
  }
}
```
